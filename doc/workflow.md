# Workflow — Процесс работы по итерациям

## Цикл одной итерации

```
1. Прочитать описание итерации в doc/tasklist.md
2. Написать/изменить ровно один модуль (минимальный diff)
3. Запустить проверку из tasklist (команда указана явно)
4. Если проверка прошла → обновить статус в tasklist.md (⬜ → ✅)
5. Сделать коммит с сообщением вида: "iter-03: chunker paragraph splitting"
6. Перейти к следующей итерации
```

## Что делать до кода

- Убедиться, что предыдущая итерация имеет статус ✅.
- Прочитать раздел «Задачи» текущей итерации.
- Проверить, что все импортируемые модули уже существуют.

## Как выполнять проверку

Каждая итерация имеет **одну команду проверки** из `doc/tasklist.md`. Запускать её буквально — без дополнительных аргументов. Если команда падает с ошибкой → итерация не завершена.

## Когда обновлять tasklist

Только после успешной проверки. Обновление tasklist — часть коммита итерации.

## Правила коммита

```
Формат: "iter-NN: краткое описание"
Пример: "iter-05: BM25 retriever + is_relevant threshold"

Не допускается:
- Коммит нескольких итераций в одном
- Коммит без прохождения проверки
- Добавление неиспользуемых зависимостей
```

## Запрещённые действия

- ❌ Переходить к следующей итерации без успешной проверки.
- ❌ Менять `app/config.py` в середине итерации без фиксации в doc/.
- ❌ Хардкодить пути — только через `app/config.py`.
- ❌ Коммитить `data/` (кроме `data/raw/sample.json`).
- ❌ Добавлять зависимость без записи в `pyproject.toml`.
